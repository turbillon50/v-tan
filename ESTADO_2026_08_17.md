## 2. Bugs de runtime confirmados

### 2.1 🔴 `text` no declarada — la ruta OpenRouter del motor legacy nunca funcionó

`artifacts/api-server/src/lib/trading-engine.ts:8487, 8498, 8500, 8525`, dentro de
`runGeminiUserCommand()` (declarada en la línea 5273). No hay ninguna declaración de `text` en
ese ámbito — la más cercana (`let text` en la 7268) pertenece a otra función.

El módulo es ESM (`"type": "module"` + salida ESM de esbuild), así que corre en modo estricto.
Verificado en este mismo entorno con Node 22:

```
READ  -> ReferenceError: text is not defined
WRITE -> ReferenceError: text is not defined
```

Efecto concreto cuando `OPENROUTER_API_KEY` está configurada y se entra a esa rama:

1. Línea 8487, `text = orRaw;` — dentro del `try` del bucle de modelos. Lanza
   `ReferenceError`, lo traga el `catch (orErr)` de la línea 8495 y se loguea como
   *"[OR-PRIMARY] modelo falló"*. **La respuesta buena de OpenRouter se descarta**, aunque el
   log de la línea anterior ya dijo "✅ exitoso".
2. Línea 8498, `if (text)` — **fuera** del try. Lanza `ReferenceError` sin nada que lo atrape.

Esto viene del commit `c210789 feat: OpenRouter como primary — Gemini ya no es requerido`
(2026-05-15), la **última feature subida antes de que el repo se detuviera**. La ruta que se
suponía que iba a hacer innecesario a Gemini nunca ejecutó correctamente ni una vez.

### 2.2 🔴 `API_URL` no declarada — búsqueda semántica de imágenes rota

`artifacts/api-server/src/mastra/tools/image-tools.ts:221`

```ts
url: imgId > 0 ? `${API_URL}/image/${imgId}` : "",
```

`API_URL` no está declarada ni importada en ningún punto del archivo (única aparición: esa
línea). `ReferenceError` en cuanto la tool devuelve al menos un resultado.

### 2.3 🟠 El prompt de voz recibe `[object Promise]`

`artifacts/api-server/src/lib/voice-live.ts:46`

```ts

```

`rulesAsPromptText()` (`lib/governance.ts:228`) es `async` y **no recibe argumentos**. Dos
fallos en una línea: se le pasa un argumento de más (TS2554) y no se le hace `await`. Como
está dentro de un `try/catch`, no rompe nada — simplemente inyecta `[object Promise]` donde
debería ir el resumen de gobernanza. La Tanit de voz **no conoce sus reglas**.

## 3. 🔴 El deploy de producción lleva roto desde el 23 de mayo

Esto no estaba previsto encontrarlo — salió porque el PR de esta auditoría disparó un deploy y
apareció un proyecto que no conocíamos: **`v-tan-api-server` en Vercel**
(`prj_g5WExKyViNzxoExEXFj45rQs1mC5`, equipo *luis' projects*, root directory
`artifacts/api-server`). O sea, el API **también se despliega en Vercel**, no solo en Railway,
y cada push a este repo dispara un deploy.

Historial de deploys con `target: production`:

| Commit | Fecha | Estado |
|---|---|---|
| `ea26775` (último de `main`) | 2026-05-23 | ❌ **ERROR** |
| `1218e6c` | 2026-05-23 | ❌ **ERROR** |
| `07d28f4` | 2026-05-23 | ❌ **ERROR** |

Los tres fallan con el mismo mensaje:

```
Error: src/lib/api-keys-provider.ts: Emit skipped
```

**Causa**: Vercel corre su propio paso de TypeScript. `tsconfig.base.json` tiene
`"noEmitOnError": true`, así que con los 152 errores de la sección 1 `tsc` no emite y Vercel
lo trata como fallo. El bundle de esbuild **sí se genera correctamente** en el mismo build
(se ve `dist/index.mjs 16.4mb ⚠️ ⚡ Done in 1377ms` justo antes del error) — el deploy muere
después, en la verificación de tipos.

Los propios mensajes de commit de mayo lo confirman: *"Esto debería desbloquear los deploys
Vercel de Tanit (**20+ ERROR seguidos** por este TS2339)"*. Fue la última batalla antes de que
el repo se detuviera, y se perdió.

**Consecuencia concreta**: lo que esté sirviendo hoy en producción es un build **anterior al
23 de mayo**. El repositorio y producción llevan tres meses divergidos. Cualquier conclusión
que saquemos leyendo este código no describe necesariamente a la Tanit que está corriendo.

*(Nota: el deploy de preview de este mismo PR también falló, con el mismo error exacto. Es un
commit que solo añade un archivo markdown — confirma que el fallo es preexistente y reproduce
en `main`, no lo introdujo esta auditoría.)*
